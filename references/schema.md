# Textoria SQLite and Search Schema

Use this reference before creating or validating SQLite and FTS outputs.

Textoria v1 uses a TEI-inspired neutral text-structure model:

```text
collection -> document -> division -> paragraph -> sentence -> token
```

Do not create fixed `books`, `chapters`, or `sections` tables. Variable middle structure such as volume, chapter, issue, date, case, file, folder, heading, or subject belongs in the single recursive `divisions` table.

## Database File

Default path:

```text
textoria/collections/<collection_slug>/sqlite/library.sqlite
```

Enable foreign keys during validation:

```sql
PRAGMA foreign_keys = ON;
```

## Tables

### collections

`collections` describes the文獻集, digital archive, or publication project, such as `台灣方志全文檢索`, `岸裡大社文書`, or `紅樓夢知識平台`.

```sql
CREATE TABLE collections (
    collection_id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    slug TEXT NOT NULL,
    title TEXT NOT NULL,
    subtitle TEXT,
    description TEXT,
    collection_type TEXT,
    language TEXT,
    created_at TEXT,
    updated_at TEXT,
    metadata_json TEXT
);
```

### documents

`documents` describes the main bibliographic or archival unit inside a collection: a book, newspaper title, diary, manuscript, contract item, file, case, edition, or holding unit.

```sql
CREATE TABLE documents (
    document_id TEXT PRIMARY KEY,
    collection_id TEXT NOT NULL,
    title TEXT NOT NULL,
    document_type TEXT,
    creator TEXT,
    date TEXT,
    publisher TEXT,
    source TEXT,
    identifier TEXT,
    language TEXT,
    rights TEXT,
    source_file TEXT,
    source_format TEXT,
    source_encoding TEXT,
    sort_key TEXT,
    char_start INTEGER,
    char_end INTEGER,
    metadata_json TEXT,
    FOREIGN KEY (collection_id) REFERENCES collections(collection_id)
);
```

Recommended metadata semantics should follow Dublin Core / DCTerms where useful:

- `title` -> `dcterms:title`
- `creator` -> `dcterms:creator`
- `date` -> `dcterms:date`
- `document_type` -> `dcterms:type`
- `identifier` -> `dcterms:identifier`
- `language` -> `dcterms:language`
- `rights` -> `dcterms:rights`
- `source` -> `dcterms:source`

Use `metadata_json` for fields that do not deserve first-class columns.

### divisions

`divisions` stores every variable middle-level text division in one recursive table. It is the database equivalent of TEI-like neutral `div` structures.

```sql
CREATE TABLE divisions (
    division_id TEXT PRIMARY KEY,
    collection_id TEXT NOT NULL,
    document_id TEXT NOT NULL,
    parent_division_id TEXT,
    level INTEGER NOT NULL,
    division_type TEXT,
    title TEXT NOT NULL,
    label TEXT,
    n TEXT,
    sort_order INTEGER NOT NULL,
    path TEXT,
    char_start INTEGER,
    char_end INTEGER,
    metadata_json TEXT,
    FOREIGN KEY (collection_id) REFERENCES collections(collection_id),
    FOREIGN KEY (document_id) REFERENCES documents(document_id),
    FOREIGN KEY (parent_division_id) REFERENCES divisions(division_id)
);
```

`level` is structural depth. `parent_division_id` defines hierarchy.

Examples:

```text
level 1: 卷上
level 2: 地理
level 3: 海防
```

`division_type` is semantic, not structural. Use a controlled-but-extensible vocabulary:

```text
volume
part
chapter
section
subsection
issue
date
entry
case
file
folder
page
column
subject
heading
unknown
```

The same `level` may use different `division_type` values across collections. Do not hard-code `level 1 = volume` or `level 2 = chapter`.

### paragraphs

`paragraphs` stores the default searchable and readable unit. Every paragraph belongs to one document and should belong to the most specific available division. If the text has no divisions, create a default division for the document instead of leaving `division_id` empty.

```sql
CREATE TABLE paragraphs (
    paragraph_id TEXT PRIMARY KEY,
    collection_id TEXT NOT NULL,
    document_id TEXT NOT NULL,
    division_id TEXT,
    paragraph_index INTEGER NOT NULL,
    text TEXT NOT NULL,
    char_start INTEGER,
    char_end INTEGER,
    source_file TEXT,
    metadata_json TEXT,
    FOREIGN KEY (collection_id) REFERENCES collections(collection_id),
    FOREIGN KEY (document_id) REFERENCES documents(document_id),
    FOREIGN KEY (division_id) REFERENCES divisions(division_id)
);
```

### sentences

`sentences` is optional in configuration but should be generated by default when sentence segmentation is enabled. It links back to paragraphs and divisions.

```sql
CREATE TABLE sentences (
    sentence_id TEXT PRIMARY KEY,
    collection_id TEXT NOT NULL,
    document_id TEXT NOT NULL,
    division_id TEXT,
    paragraph_id TEXT NOT NULL,
    sentence_index INTEGER NOT NULL,
    text TEXT NOT NULL,
    char_start INTEGER,
    char_end INTEGER,
    metadata_json TEXT,
    FOREIGN KEY (collection_id) REFERENCES collections(collection_id),
    FOREIGN KEY (document_id) REFERENCES documents(document_id),
    FOREIGN KEY (division_id) REFERENCES divisions(division_id),
    FOREIGN KEY (paragraph_id) REFERENCES paragraphs(paragraph_id)
);
```

### tokens

`tokens` is optional in configuration but should be supported by the schema. It can represent whitespace tokens, rule-based Chinese tokens, or later tokenizer output.

```sql
CREATE TABLE tokens (
    token_id TEXT PRIMARY KEY,
    collection_id TEXT NOT NULL,
    document_id TEXT NOT NULL,
    division_id TEXT,
    paragraph_id TEXT,
    sentence_id TEXT,
    token_index INTEGER NOT NULL,
    text TEXT NOT NULL,
    normalized_text TEXT,
    char_start INTEGER,
    char_end INTEGER,
    token_type TEXT,
    metadata_json TEXT,
    FOREIGN KEY (collection_id) REFERENCES collections(collection_id),
    FOREIGN KEY (document_id) REFERENCES documents(document_id),
    FOREIGN KEY (division_id) REFERENCES divisions(division_id),
    FOREIGN KEY (paragraph_id) REFERENCES paragraphs(paragraph_id),
    FOREIGN KEY (sentence_id) REFERENCES sentences(sentence_id)
);
```

### source_files

`source_files` records original and prepared files for provenance.

```sql
CREATE TABLE source_files (
    source_file_id TEXT PRIMARY KEY,
    collection_id TEXT NOT NULL,
    document_id TEXT,
    original_path TEXT NOT NULL,
    prepared_path TEXT,
    extracted_text_path TEXT,
    file_format TEXT NOT NULL,
    detected_encoding TEXT,
    byte_size INTEGER,
    line_count INTEGER,
    sha256 TEXT,
    sort_order INTEGER,
    metadata_json TEXT,
    FOREIGN KEY (collection_id) REFERENCES collections(collection_id),
    FOREIGN KEY (document_id) REFERENCES documents(document_id)
);
```

### metadata

`metadata` is an optional key-value extension table for collection/document/division/unit metadata that should remain queryable but does not need a first-class column.

```sql
CREATE TABLE metadata (
    metadata_id TEXT PRIMARY KEY,
    subject_table TEXT NOT NULL,
    subject_id TEXT NOT NULL,
    key TEXT NOT NULL,
    value TEXT,
    scheme TEXT,
    language TEXT,
    source TEXT
);
```

## Indexes

```sql
CREATE INDEX idx_documents_collection ON documents(collection_id);
CREATE INDEX idx_divisions_collection ON divisions(collection_id);
CREATE INDEX idx_divisions_document ON divisions(document_id);
CREATE INDEX idx_divisions_parent ON divisions(parent_division_id);
CREATE INDEX idx_divisions_path ON divisions(path);
CREATE INDEX idx_paragraphs_collection ON paragraphs(collection_id);
CREATE INDEX idx_paragraphs_document ON paragraphs(document_id);
CREATE INDEX idx_paragraphs_division ON paragraphs(division_id);
CREATE INDEX idx_sentences_paragraph ON sentences(paragraph_id);
CREATE INDEX idx_tokens_sentence ON tokens(sentence_id);
CREATE INDEX idx_source_files_collection ON source_files(collection_id);
CREATE INDEX idx_metadata_subject ON metadata(subject_table, subject_id);
```

## FTS5

Create FTS over paragraphs by default. Paragraphs are the primary reading and search-hit unit.

```sql
CREATE VIRTUAL TABLE paragraphs_fts USING fts5(
    paragraph_id UNINDEXED,
    collection_id UNINDEXED,
    document_id UNINDEXED,
    division_id UNINDEXED,
    document_title,
    division_path,
    division_title,
    text,
    tokenize = 'unicode61'
);
```

Populate it from the archive tables:

```sql
INSERT INTO paragraphs_fts (
    paragraph_id,
    collection_id,
    document_id,
    division_id,
    document_title,
    division_path,
    division_title,
    text
)
SELECT
    p.paragraph_id,
    p.collection_id,
    p.document_id,
    p.division_id,
    d.title,
    COALESCE(v.path, ''),
    COALESCE(v.title, ''),
    p.text
FROM paragraphs p
LEFT JOIN documents d ON p.document_id = d.document_id
LEFT JOIN divisions v ON p.division_id = v.division_id;
```

Optional sentence FTS may be created when sentence-level search is requested:

```sql
CREATE VIRTUAL TABLE sentences_fts USING fts5(
    sentence_id UNINDEXED,
    paragraph_id UNINDEXED,
    collection_id UNINDEXED,
    document_id UNINDEXED,
    division_id UNINDEXED,
    text,
    tokenize = 'unicode61'
);
```

## Validation Queries

Run at least these checks:

```sql
SELECT COUNT(*) FROM collections;
SELECT COUNT(*) FROM documents;
SELECT COUNT(*) FROM divisions;
SELECT COUNT(*) FROM paragraphs;
SELECT COUNT(*) FROM paragraphs_fts;
```

Check recursive division integrity:

```sql
SELECT child.division_id
FROM divisions child
LEFT JOIN divisions parent ON child.parent_division_id = parent.division_id
WHERE child.parent_division_id IS NOT NULL
  AND parent.division_id IS NULL;
```

Check paragraph linkage:

```sql
SELECT p.paragraph_id
FROM paragraphs p
LEFT JOIN documents d ON p.document_id = d.document_id
WHERE d.document_id IS NULL;
```

Check that FTS returns rows for a sample term selected from the text:

```sql
SELECT paragraph_id, snippet(paragraphs_fts, 7, '<mark>', '</mark>', '...', 12)
FROM paragraphs_fts
WHERE paragraphs_fts MATCH ?;
```

The database is invalid if there are paragraph rows but zero FTS rows.
